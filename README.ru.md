# Audexa

**Платформа управления и автоматизации воспроизведения аудио**

Audexa - настольное приложение для Windows, предназначенное для управления аудиотекой и воспроизведением звука в помещениях и зонах. Оно разрабатывается для выставок, музеев, визит-центров, интерактивных инсталляций и других общественных пространств.

**Audexa можно установить из готового релиза или собрать из исходного кода.**

## Скачать и установить

Audexa распространяется как самостоятельное настольное приложение для Windows x64. Для установки опубликованного релиза не нужны Git, Node.js или .NET SDK.

1. Откройте [последний релиз на GitHub](https://github.com/Vludd/audexa-desktop/releases/latest).
2. В разделе **Assets** скачайте установщик `Audexa-Setup-<version>-x64.exe`.
3. Запустите установщик и следуйте инструкциям.
4. Откройте Audexa из установленного приложения или с помощью созданного ярлыка.

В релизе также может быть доступен ZIP-архив приложения - для тех, кому удобнее архивный вариант. Для стандартной установки используйте установщик.

### Обновление Audexa

Audexa умеет проверять наличие официальных релизов прямо из приложения. Если доступно обновление, откройте **Настройки → Обновления Audexa**, проверьте обновления и нажмите **Установить обновление**.

Также можно скачать установщик из более нового [релиза GitHub](https://github.com/Vludd/audexa-desktop/releases) и запустить его вручную.

> **Примечание:** опубликованные сборки предназначены для Windows x64. Перед ручным обслуживанием или устранением неполадок сделайте резервную копию важных пользовательских данных.

## Возможности

- Управление аудиотекой: загрузка, просмотр, потоковое воспроизведение, переименование и удаление файлов.
- Извлечение метаданных аудио: длительность, частота дискретизации, число каналов, формат и размер файла.
- Локальное хранение данных в SQLite, а аудиофайлов - отдельно на диске.
- Интерфейс на React внутри настольной оболочки на C# с использованием WebView2.
- Проверка официальных релизов и установка обновлений из приложения.
- Поддержка HTTP Range для потокового воспроизведения и перемотки.

## Архитектура

Audexa работает локально в Windows. Интерфейс React отображается внутри настольной оболочки, а ASP.NET Core запускается отдельным локальным процессом. Фронтенд взаимодействует с бэкендом через HTTP/REST. Бэкенд хранит структурированные данные в SQLite, а аудиофайлы - отдельно в каталоге данных пользователя.

```text
┌───────────────────────────────────────────┐
│              Audexa Desktop               │
│          оболочка C# / WebView2           │
│  ┌─────────────────────────────────────┐  │
│  │ React + TypeScript + Vite frontend  │  │
│  └──────────────────┬──────────────────┘  │
└─────────────────────┼─────────────────────┘
                      │ HTTP / REST
                      ▼
┌───────────────────────────────────────────┐
│          Бэкенд ASP.NET Core              │
│      Controllers · Services · EF Core     │
└─────────────────────┬─────────────────────┘
                      │
              ┌───────┴────────┐
              ▼                ▼
         База SQLite       Аудиофайлы
                          локально на диске
```

Модуль обновления устанавливает официальные релизы. Сборка релизов выполняется через GitHub Actions.

## Структура репозитория

```text
audexa-desktop/
├── frontend/           # Интерфейс React, TypeScript, Vite
├── backend/            # API ASP.NET Core, EF Core, SQLite
├── desktop/            # Настольная оболочка Windows и проекты обновления
├── scripts/            # Скрипты сборки и упаковки
└── .github/workflows/  # CI и workflow релизов
```

В процессе развития проекта точная структура подкаталогов может меняться.

## Разработка

Этот раздел предназначен для разработчиков, которые хотят запускать Audexa из исходного кода или вносить изменения. Для установки готового релиза перечисленные инструменты **не нужны**.

### Требования

Для разработки в Windows понадобятся:

- Git
- Node.js (рекомендуется LTS)
- pnpm
- .NET 8 SDK
- WebView2 Runtime, если он ещё не установлен

Некоторые процессы упаковки настольного приложения рассчитаны на Windows.

### 1. Клонирование монорепозитория

```powershell
git clone https://github.com/Vludd/audexa-desktop.git
cd audexa-desktop
```

### 2. Запуск бэкенда

Откройте терминал в корне репозитория:

```powershell
cd backend
dotnet restore
dotnet build
dotnet run
```

В конфигурации разработки API использует адрес:

```text
http://localhost:5081
```

Если бэкенд запущен в окружении Development, Swagger UI доступен по адресу `http://localhost:5081/swagger`.

Если миграции базы данных нужно применить вручную, установите инструмент EF Core CLI и выполните команду из каталога проекта бэкенда:

```powershell
dotnet ef database update
```

### 3. Запуск фронтенда

Во втором терминале из корня репозитория выполните:

```powershell
cd frontend
pnpm install
pnpm dev
```

Vite выведет локальный адрес в терминал.

По умолчанию фронтенд обращается к API по адресу `http://localhost:5081`. Чтобы изменить адрес, создайте файл `frontend/.env.local`:

```dotenv
VITE_API_URL=http://localhost:5081
```

После изменения переменных окружения перезапустите Vite. Настройки CORS бэкенда должны разрешать запросы с адреса разработки фронтенда.

### 4. Сборка и проверка фронтенда

Из каталога `frontend/` выполните:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm lint
```

Доступные команды фронтенда:

```powershell
pnpm dev       # Запуск сервера разработки Vite
pnpm build     # Создание production-сборки
pnpm preview   # Локальный просмотр production-сборки
pnpm lint      # Проверка ESLint
pnpm format    # Форматирование через oxfmt
```

### 5. Сборка бэкенда

Из каталога `backend/` выполните:

```powershell
dotnet restore
dotnet build
```

Перед отправкой изменений запускайте тестовые проекты, если они присутствуют в текущей версии репозитория.

### 6. Сборка настольного приложения

В репозитории предусмотрен PowerShell-скрипт сборки:

```powershell
.\scripts\build.ps1
```

Запускайте его из корня репозитория. Поддерживаемые параметры и выходные каталоги следует проверять по скрипту в текущей версии. Официальный процесс подготовки релизов описан в workflow GitHub Actions.

## Локальное хранение данных

В документации бэкенда описана следующая структура хранения данных аудиотеки:

```text
%APPDATA%\Audexa\
├── audexa.db
└── Audio\
    └── <аудиофайлы с именами на основе UUID>
```

SQLite хранит метаданные аудио, а сами файлы находятся отдельно. UUID в имени файла предотвращает конфликты, когда пользователи загружают файлы с одинаковыми исходными именами.

> Перед ручным изменением файлов или проверкой восстановления и обновления сделайте резервную копию каталога данных приложения. Не считайте, что удаление или повторная установка автоматически сохраняет данные, пока это отдельно не проверено.

## API аудиотеки

Текущая интеграция аудиотеки использует следующие эндпоинты:

| Операция | Метод и эндпоинт |
|---|---|
| Проверка состояния | `GET /api/health` |
| Получение списка аудиофайлов | `GET /api/audio` |
| Получение аудиофайла | `GET /api/audio/{id}` |
| Загрузка аудиофайла | `POST /api/audio/upload` |
| Потоковое воспроизведение | `GET /api/audio/{id}/stream` |
| Переименование аудиофайла | `PUT /api/audio/{id}` |
| Удаление аудиофайла | `DELETE /api/audio/{id}` |

Загрузка выполняется через `multipart/form-data`, поле называется `file`. В документации бэкенда указаны форматы MP3 и WAV и ограничение загрузки в 500 МБ. Потоковое воспроизведение поддерживает HTTP Range, поэтому можно перематывать запись без загрузки всего файла в память.

## Релизы

Официальные версии публикуются в разделе [GitHub Releases](https://github.com/Vludd/audexa-desktop/releases). Workflow релиза собирает приложение и публикует файлы, включая установщик Windows, ZIP-архив и метаданные обновления, которые использует встроенный модуль обновления.

Инструкции по подготовке релизов и устранению неполадок находятся в `.github/workflows/release.yml` и скриптах репозитория. При изменении механизма обновления проверяйте успешную установку, повторный запуск приложения, сохранность пользовательских данных и сценарии сбоя/отката.

## Примечания для разработчиков

- При изменении аудиотеки поддерживайте согласованность API-контрактов фронтенда и бэкенда.
- При изменении схемы базы данных добавляйте файлы миграций EF Core в Git.
- Храните пользовательские данные вне каталога установки приложения.
- Не коммитьте локальные базы данных, загруженные аудиофайлы, секреты и конфигурацию конкретной машины.
- При изменении модуля обновления проверяйте как штатную установку, так и обработку ошибок и откат.
